# 旧版 Android TV 兼容与首次真机安装

2026-11-23，应用版本 0.2.1-preview。

## 触发问题

首次连接到的小米 MiTV-ASTP0 使用 Android 9 / API 28，系统 WebView 66.0.3359.158。0.2.0 的 WebView 110 门槛使该电视无法进入白板。本次保留电视系统组件，通过 APP 内的兼容路由解决展示需求。

## 实现

- WebView 110+ 继续使用原有完整电视网页；66–109 加载 /legacy-tv.html；低于 66 提示更新浏览组件。目前只有上述 WebView 66 机型有真机证据，不代表所有中间版本都验收通过。
- 兼容页使用 Canvas 2D 和普通 DOM，构建语法目标 chrome66，不加载 React、Konva 或 Yjs 编辑器运行时。二维码仍使用原有 QRCode 库。
- legacyTV hello 强制只读；ready.snapshot 提供笔迹与对象，最终操作更新合并为最多约 10 次/秒的完整快照通知。临时笔迹、对象预览与指针继续实时广播。
- 快照包含删除 ID，避免其他成员尚未结束的预览重新显示已删除对象。保存与权限仍使用同一服务端命令和持久化链路。
- 兼容页保留建房、扫码加入、完整总览、手动适配、手机认领主持权限、自动重连和最近房间恢复。完整管理在认领后的手机端完成；兼容页暂不提供关注指定成员或平滑镜头插值。
- 原生路由恢复只保留同源房间 ID；不将邀请凭证写入原生 URL 偏好。debug APK 可通过已授权 ADB 调试自身 WebView，release 不启用此开关。
- 电视逻辑视口 960×540 时，缩小二维码面板，避免遮挡底部“适配全部内容”。

完整快照主要用于少量旧电视展示；文档很大或旧电视较多时，网络和序列化成本需要后续压测，尚不能据此声称 10 人性能达标。

## 已执行验证

- npm test：12/12，新增兼容客户端强制只读、快照与预览、删除标记用例。
- npm run build：TypeScript 和网页/服务构建通过。
- Playwright：8/8，包含兼容电视建房、编辑端文字/笔迹预览、手机主持二维码与刷新恢复；原有编辑器全部场景回归通过。
- Android assembleDebug、testDebugUnitTest（5 项）、lintDebug 通过，APK 签名验证通过。Lint 仍为已说明的横屏与矢量横幅警告。
- 已通过用户授权的 ADB 在 MiTV-ASTP0 安装并启动 0.2.1；配置内网服务，真实电视打开二维码白板。
- 实际 WebView 66 接收独立 Chromium 编辑端的文字草稿、便签、笔迹草稿和指针；最终内容落盘。测试只清除本次自动化客户端发送的对象 ID，保留其他成员内容。
- 关闭 APP 进程后重新打开，自动恢复同一房间和已有 3 个对象/8 条笔迹；最终 WebView 无运行时异常或控制台错误，二维码面板与底部按钮无重叠。
- 真实电视截屏分辨率 1920×1080，CSS 视口 960×540。手机端为 Chromium 模拟视口，不能代替物理摄像头扫码和手机软键盘验收。

本轮没有更新电视系统 WebView，也没有修改其他应用或系统设置。设备授权由用户在电视端完成。后续继续真机遥控器完整流程、其他机型、触控笔、容量与长时运行验证。
