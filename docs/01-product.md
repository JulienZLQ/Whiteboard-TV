# 产品需求与边界

版本 0.1，2026-11-23。目标是让一个房间中的人同时创造内容，电视成为公共观察面。首先服务 2–10 人共创；更大房间规模需压测后决定。

## 用户与权限

| 角色 | 可以做什么 |
| --- | --- |
| 主持人 | 创建、恢复、关闭房间，管理加入，移除成员，控制电视镜头，保存与导出 |
| 编辑者 | 编辑共享内容，独立移动视角，撤销自己的操作 |
| 观看者 | 查看内容，不修改文档 |
| 电视设备 | 只读订阅画布与在场状态，通过设备凭证请求有限的展示控制 |

电视启动创建房间并获得展示凭证，屏幕展示普通加入二维码与独立的主持人认领入口。主持人需遥控器批准或电视显示的一次性认领码；普通加入二维码不能直接授予管理权。房间不能通过可猜测的短编号直接取得编辑权限。

## 核心旅程

1. 电视打开应用，创建新白板或恢复授权过的白板。
2. 显示加入二维码、人数和连接状态。手机扫码进入网页，输入昵称，取得该房间的编辑或观看权限。
3. 手机与 Pad 显示完整内容，各自缩放和移动。新加入者默认适配已有内容。
4. 用户绘制、输入、移动对象时，其他设备即时看到过程；电视显示成员颜色、昵称和操作状态。
5. 主持人可聚焦选区或跟随一名参与者。编辑者的镜头仍然独立。
6. 结束后文档持久保存；关闭房间撤销编辑会话和旧邀请。重新开放需新的邀请。

## 电视完整画布规则

“完整”指所有未删除内容的包围盒均落入电视内容区域，不是保证无限内容始终具有可读字号。空画布采用默认 16:9 工作区域；没有内容时不以远端指针扩张范围。

总览模式自动适配内容包围盒，预留约 5% 安全区。新增内容超出边界时平滑扩张；操作进行中不自动收缩，避免镜头抖动。停止操作 2 秒后可重新适配，具体阈值在 M1 验证。过程中的草稿笔迹也计入显示范围。极远处新增内容提示主持人定位，不能静默隐藏。

主持人聚焦是明确标识的临时模式，可用“返回总览”恢复完整画布。多人同时绘制时不自动追逐最新操作者。大量内容可分区整理和使用框架；不承诺无限缩小仍清晰。

## 功能范围

| 能力 | 首次交付 | 需求 |
| --- | --- | --- |
| 扫码加入、昵称、成员颜色 | M2 | 真实跨设备连接，显示加入失败与重试 |
| 独立视角、全局总览 | M1/M2 | 个人缩放不改变电视镜头 |
| 实时指针与操作过程 | M2 | 草稿笔迹、拖动预览、选中状态；触屏接触时显示指针 |
| 手写、画笔、橡皮 | M2/M3 | 钢笔、荧光笔、颜色粗细；首版橡皮删除整条笔迹 |
| 文字、便签、形状、连线 | M3 | 中文输入法、多行文字、对象移动与缩放 |
| 贴图 | M3 | 相册/文件导入；桌面剪贴板作增强；旋转、缩放 |
| 脑图 | M4 | 根节点、子节点、同级节点、编辑、折叠、分支移动、自动布局 |
| 保存、重连、撤销重做 | M2/M3 | 撤销仅针对本人；浏览器刷新后恢复已确认内容 |
| 导出 | M3/M4 | 可恢复 JSON、PNG；超大图限尺寸或分区导出 |
| 电视 APK、遥控器与真机适配 | M5 | 安装启动、焦点导航、返回键、断网恢复、长时运行 |

首个可体验版本 M2 包含扫码、多人指针、手写、独立镜头和基本保存。完整首版是 M5，包含文字、图片、脑图和电视安装包。两者不能混称完成。

## 暂缓范围

语音/视频会议、飞书账号和文档集成、AI 自动脑图、手写识别、Office/PDF 深度编辑、无限人数、跨房间对象引用、企业组织权限和完整离线协作均不进入首版。原生 iOS/Pad APP、Apple TV、Tizen 和 webOS 分别立项，不假设一份 APK 通用。

## 初始容量与成功标准

以 1 台 1080p 电视、10 台编辑设备、单房间 2,000 个对象/约 100,000 个笔迹点作为首轮测试场景，图片解码预算单独管理。4K 输出列入适配测试，不等于按 4 倍像素无限增加缓存。

目标：已打开扫码器后 15 秒内完成加入；同区域稳定网络下远端过程显示 p95 ≤ 200 ms；手机本地输入到显示 p95 ≤ 50 ms；电视常规互动 ≥ 30 fps。以上是待实测目标，不是现有表现。
