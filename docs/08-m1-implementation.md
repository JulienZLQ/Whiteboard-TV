# M1 工程与协作实验

> 本文保留 M1 阶段记录。当前邀请、权限和电视镜头行为已升级，见 [M2 说明](09-m2-collaboration.md)。运行命令仍适用。

此阶段交付可运行的浏览器实验版，用于检验电视总览与独立编辑视角。它不是完整的电视 APK，也不代表 M1 真机门槛已经全部通过。

## 已实现的行为

- React/Vite 前端、TypeScript 共享画布模型、Node WebSocket 服务与 npm workspaces。
- 创建白板、昵称加入、编辑链接二维码、单独的电视只读链接。
- Konva 画笔、荧光笔、整条笔迹擦除；桌面拖动/缩放、触摸双指平移/缩放。
- 各设备独立镜头；电视按全部内容和活动草稿适配。
- 真实网络指针和笔迹预览；预览 TTL 清理，最终提交覆盖预览。
- Yjs 文档更新、服务端校验操作、单房间串行持久化、磁盘原子快照与重启恢复。
- 短断线待发送队列、刷新后的会话恢复、JSON 本地副本导出。
- 电视只读凭证不能提交笔迹；不同房间隔离；消息、点数与对象数量限制。

## M1 有意缩小的范围

电视上的邀请二维码目前是**观看邀请**；可编辑二维码从编辑端打开。M2 将实现电视创建房间、一次性主持人认领和限时编辑邀请。

邀请暂为长随机能力链接，不提供账号、撤销、过期与主持人管理。服务默认仅监听 127.0.0.1；本阶段不作为公网服务部署。二维码遇到 localhost 会明确提示手机不可访问。

持久化暂用本地文件快照而非 PostgreSQL。每次完成操作都写快照并 fsync，适合低容量验证，不能据此宣称已满足 10 人/2,000 对象的性能目标。多服务实例与大文档写入性能待 M2 后续验证。

客户端提交经过校验的 commit/delete 命令，由单实例服务更新 Y.Doc，再广播 Yjs 增量。并非允许任意客户端上传二进制 Yjs 更新，也不是完整点对点 CRDT 离线协作。此取舍避免在 M1 把未校验文档写入权威状态。

短断线队列存在当前标签页的 sessionStorage。关闭标签页后不保证保留未保存内容；保存失败时请保持页面并导出副本。JSON 导入、撤销重做、文字、贴图、脑图、完整离线模式尚未实现。

电视当前即时适配包围盒，尚无平滑扩张、延迟收缩或主持人聚焦；这一点与最终设计有差距，需要 M2 完成。长笔迹自动分段；压力笔、防手掌误触、遥控器导航与 APK 尚未验证。

## 代码结构

- apps/web/src/session.ts：连接、重连、待保存队列、Yjs 文档和临时预览。
- apps/web/src/canvas/engine.ts：Konva 渲染、指针事件、手势与本地镜头。
- apps/web/src/components：工具栏、二维码弹窗、编辑端/电视端界面。
- apps/server/src/server.ts：HTTP、WebSocket、角色检查与操作顺序。
- apps/server/src/store.ts：元数据、Yjs 快照、原子写入与恢复。
- packages/board-core：世界坐标、总览计算、数据类型与输入约束。
- tests：多浏览器集成场景；.github/workflows/ci.yml：构建、单元/集成和浏览器验证。

## 运行

需要 Node.js 22.12+ 和 npm。

```sh
npm ci
npm run dev
```

开发界面默认 http://127.0.0.1:5173，协作服务默认 8787。Vite 代理 API 与 WebSocket。若端口已占用，停止自己的旧实例或修改配置，不要终止无关服务。

生产方式的本地试用：

```sh
npm run build
npm start
```

浏览器打开 http://127.0.0.1:8787。默认数据目录为启动进程工作目录下的 .data，可通过 DATA_DIR 指定；运行过程中不要删除数据目录。备份时先停止服务，再复制该目录。文件包含访问凭证，请勿提交到 Git。

同一受信局域网的人工试用可明确指定 HOST=0.0.0.0 与 PORT，再从设备访问该主机局域网地址。需要自行确认防火墙和网络可达性；这不应直接映射为公网端口。安全部署与 HTTPS 配置留到 M2 的房间权限完善之后。

```sh
npm test
npm run build
npx playwright install --with-deps chromium --no-shell
npm run test:e2e
```

浏览器测试默认独立使用 18787 端口，可用 WB_TEST_PORT 覆盖。Playwright 使用完整 Chromium。测试覆盖能力不能替代 iPhone、iPad 触控笔和真实 Android TV 的验证。

## 视觉实现规范

选用的概念为浅灰点阵画布、白色浮动面板、蓝色主按钮、蓝/紫/橙画笔。界面文本和图标以代码实现，没有把概念图作为可点击界面。

设计变量：背景 #F7F8FA、正文 #172033、强调 #315EFB、边界 #E2E6EC；面板圆角 18px、工具选中圆角 10px；桌面标题 22px、控件 14px；移动端工具置底，电视端隐藏编辑工具。图标采用同一线性图标集。字体优先系统中文字体，不依赖运行时外部字体服务。

概念中的示范笔迹、成员姓名均不是预置业务数据，实际画布从空白开始；成员和指针只来自真实连接。为表达真实状态，增加空画布引导、断线/待保存提示和导出本地副本；这些是必要功能状态的明确扩展。
