# M3 贴图与电视视图优化

更新：2026-11-23。本轮继续既有开发分支，保留原白板数据、会话和已安装的 0.2.1-preview Android TV 外壳。

## 用户流程

手机 / Pad 点击工具栏“添加图片”，从相册或文件中选择 JPG、PNG、WebP。压缩上传完成后，图片出现在自己的当前视角中央并自动选中；拖动图片移动位置，拖动右下蓝色方块等比缩放，也可以使用“缩小 / 放大”按钮。电视和其他编辑端实时看到拖动、缩放过程；松手后保存。图片可删除，笔迹位于图片上方，可直接标注。

电视二维码支持收起和重新显示，收起后总览释放右侧空间。新旧电视页面都可关注成员，关注只改变当前电视的镜头；成员暂时停笔后保留最后一个指针位置。点击“适配全部内容”回到总览。旧电视用遥控器依次选中“完整画布”按钮，每次确认切换一个在线编辑成员，最后回到总览。没有指针位置时继续总览，成员离开后自动回到总览。

## 模型与同步

- `BoardObject` 为文字/便签与图片的联合类型。图片包含 `id/kind/x/y/assetId/width/height`，不接受外部图片 URL。
- 图片文件单独存储；Yjs、WebSocket、离线队列中只有资源 ID 与几何属性，避免反复发送图片数据。
- 上传完成且文件存在于本房间后才接受创建对象；服务端过滤字段，不接受通过文字更新修改图片内容。
- 移动 `{x,y}` 与缩放 `{width,height}` 分字段提交，各自原子更新；同字段并发采用最后持久化值。过程预览不会写入文档。
- 删除墓碑和操作 ID 去重沿用已有机制，迟到的移动/缩放不使对象复活。
- 老房间文件仍为 schemaVersion 1，原有文字/笔迹无需迁移。

## 图片资源

- 上传：`POST /api/rooms/:roomId/images`；读取：`GET /api/rooms/:roomId/images/:assetId`。
- 两者要求当前房间的 `Authorization: Bearer ...`；上传还要求个人编辑/主持凭证、`X-Whiteboard-Client: 1` 及 `Content-Type: image/png`。邀请本身不能用于资源接口，需先加入兑换个人凭证。
- 读取允许有效主持、个人编辑或观看凭证；不允许其他房间、被移除成员或已结束会话。URL 不含凭证，响应不缓存，不开放 CORS。
- 原图上限 20 MB、30M 像素；浏览器重新编码为 PNG，去除原图元数据，最长边不超过 1280，超过 1 MiB 时继续下采样。透明像素保留；不支持动图、SVG、HEIC、裁剪或旋转。
- 服务端校验 PNG 签名、IHDR、颜色与位深、尺寸、分块完整性、CRC、IEND，并限制解压输出长度。只支持非交错 8-bit RGB/RGBA。
- 每房间最多保存 20 个不同图片文件，重复字节按 SHA-256 去重；文件存于 `DATA_DIR/images/:roomId/:assetId.png`，fsync 后原子改名。
- 删除画布对象不会立即删除文件；上传后中断、未插入或已删除的图片仍占额度，避免破坏重试或已有副本引用。本轮不做自动资源回收；后续应提供可恢复的归档/清理方案。
- 上传最多同时处理 4 个请求，单次 15 秒读取超时；资源写入加入房间串行队列，重新检查撤权与结束状态。

## 渲染与导出

现代画布使用 Konva.Image；WebView 66 电视使用 Canvas 2D。两者以带鉴权的 fetch 获取资源，再通过 Blob URL 解码，缓存解码结果；页面销毁释放资源。失败后重试，断网恢复触发重绘。单页面限制图片缓存条目，图片不会嵌入旧电视的完整 JSON 快照。

手机 / Pad 导出含图文档时使用 JSON schemaVersion 3，`assets` 收录被当前对象引用的 PNG data URL。不含图片的文档继续导出 v2。资源读取失败时明确提示导出失败，避免生成缺少图片的“完整副本”。导出功能尚不提供导入恢复；完整服务备份必须同时包含房间 JSON 和 images 目录。结束会话后或离线时，含图完整导出受资源读取权限/网络限制，应在结束前导出。

## 更新与兼容

本轮更新服务器和网页资源，不需要重新安装 APK。既有打开的手机网页需刷新加载新编辑器，电视需重新加载网页，之后再使用图片。新服务兼容旧文档；旧前端不认识图片对象，因此不要同时保留旧页面继续编辑含图白板。

升级服务前保留房间文件备份，使用独立发布目录，原数据目录保持不变。内网服务地址继续使用原配置；未开启公网访问或 NAS 开机自启。
