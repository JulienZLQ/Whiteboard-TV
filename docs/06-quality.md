# 验收与测试计划

以下均为待执行验收，不是测试结果。以可复现操作、设备和网络条件为证据；自动化与真机结果分别记录。

## 核心场景

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| A01 | 电视创建房间，两台手机和一台 Pad 扫码 | 加入同一内容，昵称可区分，电视只读 |
| A02 | A 放大左上，B 平移右下 | A、B 镜头互不影响，电视仍总览 |

| A05 | A 撤销，B 同时编辑其他对象 | 仅撤销 A 的目标操作，B 的更改保留 |

## 自动化分层

单元测试覆盖坐标变换、总览算法、节点布局、输入校验、版本迁移和操作分组。集成测试使用真实协作服务和数据库，覆盖多客户端、权限、乱序、去重、断线与崩溃恢复。

浏览器端到端测试使用独立上下文模拟不同设备与用户；至少一个用例跨独立进程通过网络连接，不能仅靠同页状态或 localStorage 假装协作。视觉回归覆盖电视、手机竖屏、Pad 横屏、中文输入和错误状态。

## 设备矩阵

- 目标 Android TV 或安卓盒子：型号、Android 版本、WebView 版本待补齐。
- 手机：iPhone Safari 与 Android Chrome 各至少一台。
- Pad：iPad Safari + 触控笔；Android 平板作为第二批适配。
- 1080p 与 4K 输出；不同 DPR、横竖屏、系统字体缩放。
- 遥控器、触控、鼠标和笔分开验证；不以桌面模拟代替触控笔验证。

## 性能测量

基准场景：10 名编辑者、1 台电视、2,000 对象、100,000 笔迹点；另测 20 张经过下采样的图片。网络分别记录 RTT、抖动、丢包和上下行带宽，正常基准采用同区域 RTT 约 50ms，另测 RTT 150ms 和 1% 丢包。

目标：本地输入显示 p95 ≤ 50ms；跨端过程显示 p95 ≤ 200ms；常规电视 ≥ 30fps；持续运行 4 小时无崩溃且内存不持续无界增长。使用输入采样、发送/接收/渲染时间点测量；跨设备时钟需校准或通过视频/往返法验证，不能直接相减未同步时钟。

同时记录加载时间、内存、CPU、消息量、快照大小和恢复时间；压力逐级上升直到出现瓶颈，再发布有证据的容量限制。

## 发布门槛

阻断发布：未授权写入、不可恢复丢数据、持续不同步、房间串数据、电视无法导航或启动、重复崩溃。次要视觉问题可记录后进入试用，但必须说明。

试用前完成全量备份与恢复演练、部署回滚、依赖许可清单、日志脱敏、资源配额和房间邀请轮换验证。确认实际域名与网络可达性后才能把二维码标为可用。
