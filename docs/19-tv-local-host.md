# 电视本地版与后续 NAS 同步边界

## 产品决定

电视是当前白板的服务主机。安装后直接进入创建页，不再输入服务器地址。手机、Pad 与电视连接同一局域网，扫码打开电视提供的网页，独立编辑并实时上屏。无需 NAS 或互联网下载网页、字体或运行时资源。

NAS 服务源代码、已有数据和旧地址偏好保留，默认界面隐藏入口。未来用于账号下的在线资产、备份和跨设备同步；本轮没有上传到 NAS，也没有实现云同步。历史 NAS 白板不会自动迁到电视。

## 运行与存储

- APK 内置网页、协作后端及 nodejs-mobile 18.20.4，共用现有 Yjs、授权、图片、操作历史和 fsync/原子替换逻辑，不维护第二套不同协议的服务。
- Android `LocalServerService` 在私有 `:local` 进程运行。Activity 绑定服务；显式退出后解绑，服务关闭连接并等待正在保存的操作结束，再退出独立进程。显示页面重载不重启后端。
- 电视始终访问 `http://127.0.0.1:8787`。固定来源保证 IP 变化后仍能读取相同 WebView 凭证；本机端口被占用时给出错误，不悄悄换端口而丢失凭证。
- ConnectivityManager 提供当前默认 Wi-Fi/以太网 IPv4。二维码使用 `http://电视IP:8787`；每 3 秒更新网络地址，无可用地址时隐藏二维码并提示联网。本轮不自动开启热点，不更改网络设置。
- 白板与图片位于应用私有 `files/boards`，NAS 配置键不变；电视本地最近房间使用独立 `localRoomUrl`。运行资源按内容哈希解包，升级不会替换白板数据。
- 内容写入文件并同步后才确认已保存。停止或进程被回收前未获确认的操作，仍由手机会话队列保留。重新打开电视后手机重连并重试。
- 新建电视白板的第一个编辑者自动成为主持人。暂停、移除、结束权限与原版一致。本地电视恢复或持续展示时可更新过期邀请；已暂停和已结束会话不会自动重新开放。
- 菜单：继续展示、重新加载、新建白板、退出应用。BACK 关闭当前弹窗或显示退出确认。退出提示说明手机连接将暂停。

## 接口与保护

`GET /api/local-info` 返回本地模式与当前加入来源；只在 Android 内置服务启用。`POST /api/local-stop` 要求本机套接字与进程启动时生成的控制密钥；密钥不进入网页或二维码。

本地服务只接受本机或当前局域网 IP 的 Host，HTTP 与 WebSocket 同时校验 Origin，拒绝域名重绑定与跨站请求。WebView 66 在 no-referrer 策略下会发送 `Origin: null`，兼容仅限本机回环套接字、固定本机 Host 和电视外壳 UA。所有房间编辑仍需现有个人凭证，图片仍需授权。

APK 不对外暴露 Android Service，不建立网页原生 JS 桥；WebView 保留同源限制、禁止文件读取、禁止跳过证书错误。局域网明文通信用于同网扫码，本版本不用于互联网公开部署。

## 构建

构建主机使用 Node.js 22.12+、JDK 17、Android SDK 35 / Build Tools 35.0.0、Gradle 8.9。

另下载官方 [nodejs-mobile Android 18.20.4](https://github.com/nodejs-mobile/nodejs-mobile/releases/tag/v18.20.4) 与 Android NDK r27c，解压后配置路径。Android ZIP SHA-256：

```
bd7321eaa1a7602fbe0bb87302df2d79d87835cf4363fbdd17c350dbb485c2af
```

```sh
npm ci
export LOCAL_NODE_HOME=/path/to/extracted-nodejs-mobile
export ANDROID_NDK_HOME=/path/to/android-ndk-r27c
npm run android:prepare
gradle -p apps/android-tv :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --no-watch-fs
```

`prepare-android-local.mjs` 打包服务为 Node 18 CJS、复制生产网页、编译 JNI 桥并放入三个 ABI 的运行库。生成资源和二进制不提交 Git。APK 内附运行时和 JS 依赖的许可说明。运行库不含 ICU，打包时让 lib0 使用其严格 UTF-8 兼容实现，避免中文白板启动失败。

运行时嵌入方式参考 [Node.js Mobile Android 指南](https://nodejs-mobile.github.io/docs/guide/guide-android/getting-started/)。其运行时每进程只能启动一次，因此独立进程退出后才能重新初始化。

## 当前边界与后续

- 预览侧载包；Android 8+，包含 armeabi-v7a、arm64-v8a、x86_64。已测设备以交付验证记录为准，不等于全部电视认证。
- 运行库 ELF 当前为 4 KB 对齐；16 KB 页大小设备尚不支持，需重建运行库并验证后再面向这些设备发行。正式上架前也需升级仍在维护的运行时、生产签名和安全审计。
- 需要设备互通的 IPv4 局域网；访客网络隔离、IPv6-only、VPN 默认路由未覆盖。
- 退出、关机或被系统回收后暂停服务。切后台时系统也可能回收，不承诺常驻；再次打开恢复已保存白板。没有开机自动启动或持续后台服务。
- 卸载/清除应用数据会删除本地白板与图片，当前不自动上传备份。新建前的旧房间仍在本机，历史白板列表、导入与备份管理列入下一步。
- 多台电视各有独立本地白板，不会自动跨电视同步。NAS 同步将基于资产标识、版本、上传队列和冲突策略单独设计，不能简单把本地路径替换为云地址。
- 后续顺序：历史白板与导入导出 → 真实手机/Pad 与多型号电视验收、容量长测 → 脑图节点编辑 → 可选 NAS 在线资产与备份。

## 本轮验证（2026-11-23）

- 类型检查与 Web / 服务端 / 内置服务打包通过；核心和服务端 25 项测试通过，包含本地 Host/Origin 拦截、关闭鉴权、网络地址变化与过期邀请恢复。
- 现有浏览器端到端测试 14 项通过。Android 单元测试 6 项通过，Lint 无错误，仅保留电视横屏的既有提示。
- MiTV-ASTP0（Android 9、WebView 66、ARM 32 位）实际安装：本机创建、二维码内容比对、首位编辑者主持权限、双浏览器编辑、真实电视指针与笔迹过程、中文/emoji、图片、撤销/重做、原生退出和重开、保存恢复与手机浏览器重连通过。
- 模拟 Android 网络地址通知，验证无 IPv4 时隐藏二维码、地址变化时更新二维码、电视本地画布保持可用；没有改动用户的 Wi-Fi 或路由器。
- 现代 Chromium 1920×1080 本地电视视图通过建房、邀请链接、断网提示与恢复验证；通过隔离的浏览器代理连接实际电视内置服务，没有占用 NAS 上其他服务端口。
- 手机端本轮使用 Chromium 390×844 模拟视口，另测 1280×800 编辑端。真实手机摄像头扫码、iOS Safari、触控笔、实际 DHCP 换网、断电和长时容量尚待后续验收。
- 原 NAS 服务与数据保留。真机测试使用独立测试房间，结束后恢复干净的本地白板。
