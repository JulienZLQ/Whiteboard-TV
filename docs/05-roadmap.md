# 里程碑与开发任务

按可验收成果推进。以下为一名有经验的全栈开发者投入、设计与测试支持可及时获得时的粗估，不是交付承诺。M1 后按真机和协作复杂度重估；参考总量 10–16 工程周，不包含应用商店审核或等待硬件。

## 阶段计划

| 阶段 | 预计投入 | 交付 | 放行条件 |
| --- | --- | --- | --- |
| M0 产品基线 | 0.5–1 周 | 本套需求、设计、架构、协议、验收文档 | 范围清楚，默认与待确认项可追踪 |
| M1 风险验证 | 1–2 周 | 工程骨架、设备探针、单机画布、双端同步实验、四端线框 | 真机渲染/输入/同步可行，选型记录冻结 |
| M2 协作闭环 | 2–3 周 | 房间、扫码、指针、草稿笔迹、独立镜头、基础保存 | 电视＋两台真实移动设备共写并恢复 |
| M3 基础编辑 | 2–3 周 | 文字、便签、形状、贴图、橡皮、撤销、导出 | 中文输入、图片与撤销并发用例通过 |
| M4 脑图 | 2–3 周 | 节点编辑、分支移动、折叠、布局、结构并发 | 不产生环或孤立错误关系，布局可复现 |
| M5 电视与试用 | 2–4 周 | APK、遥控器适配、完整视觉、性能、部署/备份/恢复 | 目标电视验收与安全/恢复测试通过 |

每阶段都更新需求状态、变更说明、验证证据和已知限制。代码通过 PR 交付，不把实验完成等同于产品完成。

## M1 可直接执行的任务

| 编号 | 任务 | 依赖 | 完成证据 |
| --- | --- | --- | --- |

| F03 | 单机笔迹、触控缩放、文字输入探针 | F02 | 手机/Pad 操作录像，记录软键盘和笔事件 |
| F04 | 电视展示路由、总览与主持人聚焦样例 | F02 | 1080p/4K 截图与目标设备帧率 |
| F05 | 双端 Yjs/WS 实验与草稿过程通道 | F02 | 两个独立浏览器看到笔画过程与最终一致性 |

## 后续工作包

M2：会话角色 → 二维码兑换 → 成员与指针 → 草稿预览 → 最终提交与持久化 → 重连 → 房间关闭与权限撤销 → 三设备验收。

M3：文字输入和选择 → 便签/形状/连线 → 图片压缩上传与鉴权 → 撤销/重做 → PNG/JSON 导出 → 移动端工具栏与视觉打磨。

M4：脑图关系模型 → 确定性布局 → 节点输入 → 分支移动与校验 → 折叠 → 多人结构操作和撤销 → 大图性能。

M5：电视平台能力检查 → APK 壳与启动入口 → 焦点导航 → 网络和生命周期 → 多小时稳定性 → 部署脚本与备份恢复演练 → 试用发布。

## 每次迭代的交付格式

交付说明应包含：新增用户能力、可访问的演示或安装产物、如何复现验证、真实通过的测试、未解决限制、下一阶段入口。不存在的演示地址、构建结果和真机结果不得补写为已完成。

首个可运行版本的验收优先级高于大而全的工具栏。脑图与高级视觉不能掩盖扫码不通、同步延迟或数据丢失等基础问题。

## 2026-11-23 推进补充

为便于真机验证，已提前实现通用 Android TV 启动外壳、服务地址设置、遥控器导航和恢复能力，并构建侧载预览 APK。此举不代表 M5 完成：原生真机、文字/贴图/脑图、容量和长时稳定性仍需各自验收。详见 [Android TV 交付说明](10-android-tv.md)。
